# CLAUDE.md

Monorepo de jeux web pour Poki (Phaser 4 + TypeScript + Vite, npm workspaces). L'utilisateur parle français :
répondre, commenter et documenter en français.

- `packages/engine` (`@xiao/engine`) : briques réutilisables. N'importe jamais un jeu.
- `games/xiao-swarm` : jeu en cours. `games/_starter` : boilerplate minimal des futurs jeux.
- **But final : un boilerplate pour produire d'autres jeux facilement.** Tout code générique (outils de dev, vagues, XP / upgrades, collisions…) va dans `packages/engine` et `_starter`, pas dans `games/xiao-swarm` (voir `docs/ROADMAP.md` § À faire 0).
- Règles de chargement des fichiers (paquets 1 / 2a / 2b), des replis et de la fabrication des textures procédurales : `docs/CHARGEMENT.md`.
- Noms et enchaînement des écrans d'interface (TitleScreen, SoloScreen, MultiplayerScreen, LobbyScreen…) : `docs/UI_ECRANS.md`.
- État et prochaines étapes : `docs/ROADMAP.md`. Game design : `docs/Xiao_Swarm_Attack_Game_Design.md`. Outils de dev : `docs/OUTILS_DEV.md`. Capacités des aliens (actives et désactivées) : `docs/ALIENS.md`. Idées pour les soldats (capacités, upgrades de boutique) : `docs/IDEES_UNITES.md`.

## Commandes
- `npm run dev` (Xiao Swarm, port 5173), `npm run dev:starter`
- `npm run typecheck` — tout le monorepo + pureté des simulations. À lancer après chaque modification.
- `npm run sim:headless -- royale 9 300` — simulation dans Node (sans navigateur)
- `npm run sim:net` — test réseau hôte + client sans navigateur. En ligne : `?net=host`, `?net=join&room=CODE`, `?net=auto` (voir `docs/MULTIJOUEUR.md`)
- `npm run sim:bot -- 300 2 7` — coéquipiers IA du coop (`sim/CoopBot.ts`, niveaux standard / expert dans `data/bots.ts`) joués sans navigateur et comparés. En jeu (dev) : `?net=host&bot=2&botlevel=expert` ou section « Coéquipiers IA » du panneau Triche.
- `npm run sim:waves` (dans `games/xiao-swarm`) — horloge de la timeline des vagues (`sim/WaveRunner.ts`) : suspension pendant un combat de boss (rejeu sans XP des 5 dernières vagues) et pause au-delà de 150 aliens (reprise à 100)
- `npm run sim:tutorial` — joue l'onboarding scripté (`sim/Tutorial.ts`, données `data/tutorial.ts`, doc `docs/TUTORIEL.md`) avec un joueur automatique.
- `npm run sim:calibrate` — lit tes parties enregistrées en dev (`docs/bench/runs/*.json`, `sim/RunRecorder.ts`) : DPS réel, `model` proposé pour `data/waves.ts`, pression subie, débit réseau (voir `docs/OUTILS_DEV.md`).
- `npm run sim:predict -- 4` — prédiction de la squad locale d'un client avec latence simulée (4 ticks par sens).
- `npm run sim:net` couvre aussi le coop (friendly fire, difficulté ×2, XP partagée et pause de choix d'upgrade, spectateur, relance).
- Tests rapides d'URL (build déployé compris) : `?jump=gling|rhino|scarab|twins|crab` (partie avancée), `?endtest=1` (16 troopers + Giant Crab déjà là, pour voir la séquence de fin), `?debug=1` (outils de dev).
- `npm run zip` — build + zip Poki (`poki-build.zip`, 8,4 Mo brut / 7 Mo zippé au 10/10 : au-dessus des 8 Mo conseillés)
- `deploy.bat` (racine) — double-clic : lance `npm run deploy` (vérifie `.env.deploy`) ; sans option, **demande** [N] version actuelle / [B] bump / [F] force ; accepte aussi `--bump` / `--force` (sans question)
- `npm run deploy` — build + upload FTP vers `REMOTE_DIR/<version>/` (identifiants dans `.env.deploy`, modèle `.env.deploy.example`) ; sans option, demande quoi faire (terminal interactif) ; `-- --bump` incrémente la version, `-- --force` écrase, `-- --no-prompt` ne pose pas la question
- `node tools/slice-sheet.mjs games/xiao-swarm/art-src/<nom>.slice.json` — découpe une planche de sprites
- `node tools/slice-*.mjs` — découpe / recolore les images d'interface (timeline, barres, boutons, cartes, icônes, slots…) : liste dans `docs/OUTILS_DEV.md` § Outils d'art ; relancer après tout changement de l'image source

**Son dans le HUD** (haut droite depuis le 17/10, **sous le bouton pause** ; en haut à gauche : pièces d'or puis diamants ; `scenes/HudScene.ts`, boutons de `view/HudButtons.ts`) : haut-parleur (bruitages) et, **en dessous**, note (musique) ; un clic **coupe / rétablit** (mute mémorisé, icône barrée ; le volume reste réglé dans Options) ; compteur de FPS en bas à droite. Menu **Options** (écran Pause, `scenes/OptionsScene.ts`) : réglettes de volume à 10 crans (`settings.ts`, lecture via `music` de l'engine ; la musique est ÷6 au cran maximal : `MUSIC_MAX_GAIN`), **Hotkeys** (page de l'écran Options, `scenes/hotkeysPage.ts`, pas sur téléphone) : le joueur réassigne les touches de **déplacement** (haut / bas / gauche / droite, défaut WASD), les **choix d'upgrade** 1 / 2 / 3 et la **relance** (R) — clic sur la touche puis appui sur la nouvelle (Échap annule ; Échap / Entrée / P refusées ; une touche déjà prise est échangée ; « Rétablir par défaut ») ; touches par code **physique** (`hotkeys.ts`, `settings.hotkeys` / `moveKeys()`, `MoveInput` de l'engine avec l'option `keyCodes`), donc WASD = ZQSD sur un AZERTY sans rien régler ; **les flèches restent toujours actives** (le pavé numérique ne déplace plus la squad) ; le tutoriel affiche les touches choisies. **Rejouer le tutoriel** (seulement en debug, `DEV_TOOLS` ; confirmation, quitte la partie), langue (**anglais par défaut**) et, en dev, **mode debug** qui affiche les boutons des outils de dev. Les réglages (musique, bruitages, mutes, zoom, FPS, debug) sont mémorisés d'une session à l'autre (`localStorage`, préfixe `xiao-swarm:` posé en tête de `settings.ts`). Par défaut : musique et bruitages au cran 5/10 (`MUSIC_DEFAULT`, `SFX_DEFAULT`) ; en dev, mode debug activé.
Outils de dev (détail : `docs/OUTILS_DEV.md`). **Console de log en jeu** (`devLog` de l'engine, fermée au départ, ² / F4 / bouton du HUD ; `?debug=1&split=1` pour voir le vrai chargement en deux paquets en ligne). **En ligne** : `?debug=1` active les outils de dev dans un build déployé (`DEV_TOOLS` de l'engine, à utiliser à la place de `import.meta.env.DEV` pour tout outil de dev ; seul le Save vers le code reste lié à `import.meta.env.DEV`). Visionneuses (boutons **en bas à gauche** du jeu en mode debug, contour **vert** pour ceux qui ouvrent une vue plein écran, ou `?viewer` / `?particles` / `?obstacles` / `?misc` / `?bonus` / `?upgrades` / `?waves` / `?mapedit` / `?sounds` / `?packs`) : **unités**
(animations, ancrage par séquence / direction, bouche du canon par frame), **particules** (`fxParams.ts`), **obstacles**
(hitbox en cercles, jeu de taches, taille : `data/obstacles.ts`) **vagues** (Gestionnaire de vagues : niveaux 1-11 de configurations (9-11 vides, prêts à remplir) + niveau « Boss » à part tirées au hasard + timeline : `data/waves.ts`) **divers** (projectiles, bonus, interface, terrain) et **carte** (zones d'obstacles de l'arène solo / coop : `data/mapZones.ts`, un obstacle tiré au hasard par zone à chaque partie avec la seed, donc identique chez tous les joueurs) et **paquets** (`PacksViewerScene` : à gauche le paquet 1, à droite 2a puis 2b, avec le poids de chaque fichier, visuels et bruitages ; une liste déroulante par asset le passe dans un autre paquet ; Save réécrit la table complète `PACK_OF` de `assets/packTable.ts` (un paquet par fichier ou `sfx:<id>`, plus de règles par défaut ni d'exceptions ; un asset absent de la table est au paquet 1), effective au rechargement ; orange = modifié depuis la dernière sauvegarde ; **les textures procédurales** (dessinées par le code, atelier de textures) sont **dans les mêmes colonnes**, sur un **fond ROSE** (fichiers sur fond bleu) : leur paquet = celui pendant lequel elles sont fabriquées (1 = avant l'affichage, 2a = défaut, 2b), mémoire estimée au lieu du poids, 🔒 = recrue assemblée (obligatoire au paquet 1) ; un seul Save réécrit `assets/packTable.ts` et `art/textureModes.ts` ; les textures créées à la demande par nature sont listées sous les colonnes ; liste **Tri** (poids décroissant ou ordre de chargement : bruitages, visuels dans l'ordre du manifeste, textures dans l'ordre de fabrication, rang affiché devant chaque nom); `assetPack` de `assets/manifest.ts`, `sfxPack` de `assets/coreSfx.ts`).
Une croix en haut à droite du panneau de chaque vue ramène au jeu ; pour changer de vue, repasser par le jeu (boutons du HUD).
**Convention de toute vue avec des valeurs réglables : boutons Save et Reset.** Save écrit les valeurs comme valeurs par défaut dans le code
(plugin Vite `games/xiao-swarm/dev-save.ts` : `config.ts`, `fxParams.ts`, `assets/manifest.ts`, `data/obstacles.ts`, `data/waves.ts`, `data/mapZones.ts`) ; Reset revient à la dernière
sauvegarde. Toute nouvelle vue de réglage doit suivre cette règle. Elles mémorisent aussi leurs réglages dans le navigateur (localStorage) : en dev ces copies masquent le code. Chaque copie est marquée avec une empreinte des
valeurs du code (`dev/staleOverrides.ts`, `dropStaleOverride` appelé en tête de chaque `load…Overrides`) : si le code par défaut a changé, la copie est supprimée
au démarrage et signalée dans le HUD (« Réglages mémorisés périmés supprimés »). **Toute nouvelle copie mémorisée doit appeler `dropStaleOverride`** avec les valeurs du code qu'elle remplace.
**Boutons ±5 % du panneau Difficulté** (`shiftAllStat` de `debugStats.ts`, `shiftCrowdSpeed`, `shiftDifficulty`) : ajoutent / retranchent 5 % **de la valeur du code** (additif, +5 puis −5 revient à l'origine) à une stat de tous les aliens (PV, vitesse, dégâts = tout chemin `damage` / `dps`, cadence = `attackCooldown`, XP, chance de recrue ; pas les orbes ni l'œuf), de toutes les classes de soldats (PV, dégâts, cadence, portée, vitesse et dispersion des projectiles), à la vitesse de la squad, à `magnetRadius` et `xpCostMul` ; le Save du panneau écrit aussi les unités modifiées. **Équilibrage sans réglage caché** : les stats de chaque unité (PV, vitesse, dégâts, portées, zombies du chaman…) sont les **valeurs réelles** de `data/aliens.ts` / `data/classes.ts` (panneau Stats de la visionneuse d'unités) : plus aucun multiplicateur global de stats. Restent dans `DIFFICULTY_DEFAULTS` (`config.ts`, curseur dans le panneau **Difficulté**, `DIFFICULTY_SECTIONS` de `debugDifficulty.ts`) : escalade et enragement des boss, multijoueur, plafonds et rejeu des vagues, aides au joueur, globes d'upgrade ; le contenu et le rythme des vagues dans le Gestionnaire de vagues. Ne pas réintroduire de multiplicateur d'équilibrage en constante cachée (ex. l'ancien `WAVE_PRESSURE`, remplacé le 08/10 par l'effectif par entrée `TimelineEntry.mul`, visible dans le Gestionnaire de vagues).

Test en navigateur : `?net=host&bot=2` (coop avec 2 coéquipiers IA) ; en dev `window.__game`, le **menu Réglages** (touche `²`/F2 ou
bouton à curseurs en haut à gauche du HUD : zoom du jeu, réglages visuels, stats) et trois panneaux dédiés ouverts par des boutons du HUD (ces menus s'ouvrent toujours à gauche, côte à côte dans l'ordre d'ouverture) :
**Foule** (sliders du mouvement de foule `CROWD` dans `config.ts`, mémorisés dans le navigateur ; **F8 / F9** = sauvegarder /
charger une config de travail), **Difficulté** (réglages globaux `DIFFICULTY` de `config.ts` : boss, escalade, multijoueur, vagues, aides au joueur ; Save / Reset ; plus aucun multiplicateur de stats d'unité : PV / dégâts / vitesse / effectifs sont dans `data/aliens.ts`, `data/classes.ts`, `data/waves.ts`) et **Triche** (ajouter / retirer des soldats par classe, faire apparaître ou tuer des aliens,
recrues, vagues, vitesse du jeu, invincibilité ; hors ligne seulement). `npm run sim:crowd` mesure la réactivité,
`npm run sim:recruit` où une recrue s'insère dans la formation.

## Jeu : structure actuelle
- Carte solo / coop : `makeArenaMap(seed)` (`data/maps.ts`) tire les obstacles dans les zones de `data/mapZones.ts` (éditeur : vue Carte). Mode de jeu : la **survie** (`survival` dans `data/modes.ts`, un seul mode depuis le 08/10 : l'ancien mode `coop` y est fusionné), jouable **seul** (hors ligne : pause, revive par pub, tutoriel, boss final ~10:00 = victoire) ou **à plusieurs** en ligne (humains et/ou coéquipiers IA, pas de tir ami, difficulté qui grandit avec les joueurs de la partie (à terre compris : on peut les réanimer), XP partagée, zones de réanimation, spectateur, relance). Ce qui change en ligne dépend de `SimConfig.online` (posé par `HostSession` / `ClientSession`), jamais du mode. Les modes **versus** (PvP) et **battle royale** viendront plus tard : **désactivés pour l'instant** (`GameScene.pickMode` joue toujours la survie, `?mode=royale` est ignoré) ; leur code reste (`MODES.royale` / `MODES.versus`, `sim:headless -- royale`).
- **Vagues en embuscade** (13/10) : chaque vague de la timeline (hors boss ; **les rejeux pendant un boss en font partie** depuis le 17/10, leurs aliens restant sans XP) a `DIFFICULTY.ambushChance` (0,1, curseur du panneau Difficulté, section Vagues) d'être une embuscade : ses aliens sortent du sol (animation d'apparition habituelle) à `AMBUSH.ahead` (330 px, `config.ts`) **devant** chaque squad, dans son sens de course (`Squad.vel`, direction au hasard si elle est immobile), dispersés de ±`AMBUSH.spread` ; `WaveRunner.trigger` tire une fois par vague (un tirage de `sim.rng` de plus par vague), `Horde.spawnAhead`. Testé par `sim:combat`.
- **Première vague jamais en cercle** (17/10) : la toute première vague d'une partie (`WaveRunner.firstWaveSent`, remis à zéro par `reset`) n'est jamais une vague en cercle, même si le tirage la désigne ; le cercle ne vaut qu'à partir de la deuxième. Les tirages de `sim.rng` ne changent pas. Testé par `sim:combat`.
- **Pas de repoussement pendant l'enfouissement** (17/10) : un alien qui **sort du sol** (animation d'apparition, `Horde.isEmerging`) ou **s'enterre** (`sinkT` du recyclage, lurker / Scarab en `lurkPhase` > 0) n'est jamais repoussé : ni par l'onde de choc du level up / du revive / du repel (`Sim.updateShockwaves`), ni par une explosion (`Sim.blastHit`), ni par le recul des coups (`Sim.damage`) ; `Horde.knockable`. Le revive mortel les détruit toujours. Testé par `sim:combat`.
- **Vagues en cercle** (17/10) : chaque vague de la timeline (hors boss, hors configuration forcée et hors tutoriel ; les **rejeux pendant un boss** en font partie, leurs aliens restant sans XP) a `DIFFICULTY.ringChance` (0,1, curseur du panneau Difficulté, section Vagues) de sortir du sol **en cercle autour de la squad d'UN joueur** tiré au hasard : tous ses aliens (les parts de toutes les squads réunies), à `RING.radius` (340 px, `config.ts`) du centre, animation d'apparition habituelle (`Horde.spawnRing`, la même fonction que la dernière vague du tutoriel). Prioritaire sur l'embuscade ; `WaveRunner.trigger` tire le cercle après l'embuscade (deux tirages de `sim.rng` de plus par vague, un troisième pour désigner la squad quand il sort). Testé par `sim:combat`.
- **Mélange des vagues (invité, depuis le 01/10, réglable depuis le 15/10)** : une vague tirée au hasard (niveau seul ; jamais un boss ni une configuration forcée, ni le panneau Triche avec une configuration précise) reçoit un groupe « invité » (`WaveRunner.trigger`) : un groupe tiré au hasard (même chance pour chaque groupe) parmi **tous les groupes de toutes les configurations** des niveaux L−1 et L+1, ajouté à hauteur de `DIFFICULTY.waveGuestShare` (0,4) de son nombre (arrondi, au moins 1 ; ajouté au groupe du même type s'il existe ; `maxPerWave` respecté). Chance : `DIFFICULTY.waveGuestChance` (1 = toujours, comme avant ; 0 = vagues exactement comme dans le Gestionnaire) et `waveGuestReplayChance` pour les rejeux pendant un combat de boss (0 = rejeux purs) ; panneau Difficulté, section Vagues. Le tirage de la chance n'utilise `sim.rng` que si elle est entre 0 et 1 (à 1, même suite aléatoire qu'avant). Exemple : un cracheur peut arriver avant 1:23 comme invité d'une vague de niveau 3.
- **Apparition des aliens** : le trou d'apparition est coupé pendant 1 s à chaque « départ de partie » (`WorldView.quietUntil`, pour les aliens déjà là à l'arrivée d'un client), sauf pendant les 4 premières secondes de jeu (`FIRST_WAVES_EMERGE`) : sinon la vague 1 (à 0 s, lue au premier tick) perdait son animation de désenfouissage (13/10). Les deux premières vagues sortent juste hors écran (`EARLY_SPAWN_DISTANCE` 610 px) : l'animation peut se jouer hors champ.
- Vagues : `data/waves.ts` (niveaux 1-11 → configurations tirées au hasard (9-11 vides, à remplir), niveau `BOSS_LEVEL` (0) = configurations de boss, forcées par la timeline via `config` et sans escorte depuis le 12/10, timeline ; **effectif par entrée** `mul` : groupes hors boss × `mul`, arrondi, au moins 1, colonne « Effectif × » et barres raccourcies dans le Gestionnaire ; la pression du build Poki 0.1.38 (ancien ×0,8 de 2:00 à 5:00 et après 6:00) est reproduite en **supprimant 30 envois** de la timeline (±1,5 % par minute) ; les vagues **rejouées** pendant un combat de boss prennent en plus × le réglage **propre au boss affronté** (`DIFFICULTY.bossReplayMulGling` / `Rhino` / `Scarab` / `Twins` / `Crab`, 0,8 par défaut chacun, panneau Difficulté, section Vagues, `WaveRunner.bossMul`)), exécutées par `sim/WaveRunner.ts`. Le gestionnaire est **figé** (`cursor` ne bouge plus) : (1) tant qu'un **boss est vivant** — il renvoie alors en boucle les `DIFFICULTY.bossReplayCount` (4 actuellement, réglable) derniers envois d'avant le boss (écarts plafonnés), dont les aliens ont `AlienState.noXp` (aucun globe d'XP : pas de farm en laissant le boss en vie) ; (2) quand il y a plus de `DIFFICULTY.wavePauseAbove` (150) aliens vivants, jusqu'à `DIFFICULTY.waveResumeAt` (100) ; `WaveRunner.suspended`. Pendant un boss, sa barre de vie (HUD) remplace la timeline en haut de l'écran.
- Sauvegarde (`localStorage`, préfixe `xiao-swarm:`) : `SAVE_VERSION` dans `settings.ts` — l'incrémenter remet à zéro chez tous les joueurs le tutoriel (`settings.tutorialDone`), le compteur de parties (`gamesPlayed`, interstitielles) et le record (`bestTime`) ; les réglages (volumes, mutes, langue, zoom…) sont conservés. Détail : `docs/TUTORIEL.md`.
- **Diamants verts et boutique de skins** (17/10) : ressource `settings.gems` (mémorisée, jamais remise à zéro par `SAVE_VERSION`), compteur en haut à droite du HUD (`HudScene.placeGems`, à gauche du bouton pause). **Solo seulement** (rien en ligne, rien dans le snapshot) : chaque boss tué (sauf le final, jumeaux = le dernier tombé) laisse un œuf ; quand on l'ouvre, un **coffre à diamants** en saute (**au-dessus de l'œuf**) (`sim/Gems.ts`, `GEM_CHEST` de `config.ts`) avec une part de son contenu déjà au sol (`DIFFICULTY.gemFreeShare`, 20 %) (ramassables comme les globes, aimant compris) ; rester à moins de 67 px d’un soldat 2 s remplit la jauge circulaire autour de l'icône rewarded (`view/GemViews.ts`), pleine = événement `gemChestReady` → `GameScene.chestAd` (`flow.interrupt`, `poki.rewardedBreak`, `flow.resume`, analytics `reward/gem_chest/interact|complete`) → vidéo vue : `Gems.adResult(id, true)`, le coffre explose en `qty` diamants (voir « Diamants des boss ») ; vidéo ratée : 4 s de pause. `gemPicked` crédite `settings.addGems`. **Boutique** (`scenes/ShopScene.ts`, `SCENES.shop`, gros bouton « Skins » au milieu à droite de `SoloScene`) : 12 skins de `data/skins.ts` (teinte des bleus des soldats et de la tête de recrue, trois rangs de prix 50 / 125 / 250 dans `SKIN_PRICES`), `settings.buySkin / equipSkin`, premier cadre « Classic » (possédé d'office) = soldats d'origine, comme le cadre « No trail » de l'onglet Trails (plus de boutons en bas, seulement Back) ; le skin passe par un « emplacement visuel » ≥ `SKIN_SLOT_BASE` (100) dans `soldierSpriteId` / `recruitSpriteId` (`WorldView.visualSlot`, hors ligne et pour ma squad seulement). ## Règles d'architecture (multijoueur battle royale ~10 joueurs prévu)
1. `games/*/src/sim/`, `data/`, `net/`, `config.ts` sont **purs** : pas de Phaser ni DOM, imports depuis
   `@xiao/engine/sim` uniquement (vérifié par `tsconfig.sim.json`).
2. Tout l'aléatoire de la simulation passe par `sim.rng` (seedé). Jamais `Math.random` dans `sim/`.
3. La simulation émet des `SimEvent` et ne touche jamais l'affichage ; `view/` lit l'état, interpole, joue les effets.
4. Toute action d'un joueur passe par `PlayerInput` ; une `Session` fait avancer la simulation (pas fixe 30 Hz).
5. Contenu = données (`data/`), logique = systèmes génériques. Code générique → engine.
6. `data/obstacles.ts` (visuel + hitbox + taches) est pur et partagé sim / affichage ; `fxParams.ts`, `settings.ts`, `debug*.ts`, `dev/` et les visionneuses sont côté affichage / dev.
7. Un champ ajouté à un objet recyclé par `Pool` (ex. `Projectile`) doit être remis à zéro à la libération.

## Poki
**Pubs activées** (`ADS_ENABLED = true` dans `packages/engine/src/poki/poki.ts` ; `false` les coupe toutes) : **rewarded** pour le revive (hors ligne, un seul par partie ; le revive du tutoriel est gratuit, « Free Revive », et sans pub) et **interstitielle entre deux parties** (« Rejouer », relance coop) mais **désactivée pour l'instant** (`INTERSTITIALS_ENABLED = false` dans `config.ts` ; une fois activée : pas avant les 3 premières parties, `FREE_GAMES`, compteur `gamesPlayed` mémorisé). **Pas de pub à la sortie d'une pause.** Les règles ci-dessous valent.
Événements SDK obligatoires (https://developers.poki.com/guide/requirements-quality), tous passent par `RunFlow` / `poki` (le moteur filtre les doublons et les appels pendant une pub) :
- `gameLoadingFinished()` : une fois, quand les assets essentiels sont chargés (`BootScene`).
- `gameplayStart()` : au **premier input du joueur** (jamais au chargement), puis à chaque retour en jeu (sortie de pause, fin du choix d'upgrade, relance).
- `gameplayStop()` : à **toute interruption** : pause, menu Options, mort, fin de partie (y compris l'écran de fin coop `gameEnd`), connexion perdue. Jamais deux de suite, jamais pendant une pub. **Le choix d'upgrade n'est PAS une interruption** : c'est du gameplay, pas de `gameplayStop`.
- `commercialBreak()` : uniquement **entre deux parties** (retry, relance coop) à partir de la 4e partie (`RunFlow.restart({ ad })`) ; jamais pendant une pub, jamais à la sortie d'une pause. Pas de timer de pub maison.
- `rewardedBreak()` : uniquement sur choix explicite du joueur (revive solo).
- Non obligatoires mais utiles : `poki.measure(...)` / `poki.measureOnce(...)` (analytics du comportement : tutoriel, paliers de temps et de niveau, boss, mort, upgrades, revive, rétention). Catalogue et règles : `docs/ANALYTICS.md` ; tout nouvel événement part de la vue (jamais de `sim/`) et s'ajoute à ce catalogue.
En ligne la partie ne se met jamais en pause (l'hôte gèlerait tout le monde) : seuls l'écran de fin et la perte de connexion émettent `gameplayStop`. Le menu Options en ligne n'arrête pas le jeu, donc pas de `gameplayStop`.
Pas de requête externe hors SDK, pas d'écran titre, `gameplayStart` au premier input, pas de timer de pub maison,
bouton rewarded jamais vert et jamais plus gros que l'option standard, jouable en incognito et avec adblock.
