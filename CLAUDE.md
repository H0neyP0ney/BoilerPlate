# CLAUDE.md

Monorepo de jeux web pour Poki (Phaser 4 + TypeScript + Vite, npm workspaces). L'utilisateur parle français :
répondre, commenter et documenter en français.

- `packages/engine` (`@xiao/engine`) : briques réutilisables. N'importe jamais un jeu.
- `games/xiao-swarm` : jeu en cours. `games/_starter` : boilerplate minimal des futurs jeux.
- **But final : un boilerplate pour produire d'autres jeux facilement.** Tout code générique (outils de dev, vagues, XP / upgrades, collisions…) va dans `packages/engine` et `_starter`, pas dans `games/xiao-swarm` (voir `docs/ROADMAP.md` § À faire 0).
- État et prochaines étapes : `docs/ROADMAP.md`. Game design : `docs/Xiao_Swarm_Attack_Game_Design.md`. Outils de dev : `docs/OUTILS_DEV.md`.

## Commandes
- `npm run dev` (Xiao Swarm, port 5173), `npm run dev:starter`
- `npm run typecheck` — tout le monorepo + pureté des simulations. À lancer après chaque modification.
- `npm run sim:headless -- royale 9 300` — simulation dans Node (sans navigateur)
- `npm run sim:net` — test réseau hôte + client sans navigateur. En ligne : `?net=host`, `?net=join&room=CODE`, `?net=auto` (voir `docs/MULTIJOUEUR.md`)
- `npm run sim:bot -- 300 2 7` — coéquipiers IA du coop (`sim/CoopBot.ts`, niveaux standard / expert dans `data/bots.ts`) joués sans navigateur et comparés. En jeu (dev) : `?net=host&bot=2&botlevel=expert` ou section « Coéquipiers IA » du panneau Triche.
- `npm run sim:waves` (dans `games/xiao-swarm`) — horloge de la timeline des vagues (`sim/WaveRunner.ts`) : suspension pendant un combat de boss (rejeu sans XP des 5 dernières vagues) et pause au-delà de 150 aliens (reprise à 100)
- `npm run sim:tutorial` — joue l'onboarding scripté (`sim/Tutorial.ts`, données `data/tutorial.ts`, doc `docs/TUTORIEL.md`) avec un joueur automatique.
- `npm run sim:calibrate` — lit tes parties enregistrées en dev (`docs/bench/runs/*.json`, `sim/RunRecorder.ts`) : DPS réel, `model` proposé pour `data/waves.ts`, pression subie, débit réseau (voir `docs/OUTILS_DEV.md`).
- `npm run sim:predict -- 4` — prédiction de la squad locale d'un client avec latence simulée (4 ticks par sens).
- `npm run sim:net` couvre aussi le coop (friendly fire, difficulté ×2, XP partagée et pause de choix d'upgrade, spectateur, relance).
- `npm run zip` — build + zip Poki
- `deploy.bat` (racine) — double-clic : lance `npm run deploy` (vérifie `.env.deploy`) ; sans option, **demande** [N] version actuelle / [B] bump / [F] force ; accepte aussi `--bump` / `--force` (sans question)
- `npm run deploy` — build + upload FTP vers `REMOTE_DIR/<version>/` (identifiants dans `.env.deploy`, modèle `.env.deploy.example`) ; sans option, demande quoi faire (terminal interactif) ; `-- --bump` incrémente la version, `-- --force` écrase, `-- --no-prompt` ne pose pas la question
- `node tools/slice-sheet.mjs games/xiao-swarm/art-src/<nom>.slice.json` — découpe une planche de sprites
- `node tools/slice-*.mjs` — découpe / recolore les images d'interface (timeline, barres, boutons, cartes, icônes, slots…) : liste dans `docs/OUTILS_DEV.md` § Outils d'art ; relancer après tout changement de l'image source

**Son dans le HUD** (haut gauche, `scenes/HudScene.ts`, boutons de `view/HudButtons.ts`) : haut-parleur (bruitages) et, **en dessous**, note (musique) ; un clic **coupe / rétablit** (mute mémorisé, icône barrée ; le volume reste réglé dans Options) ; compteur de FPS en bas à droite. Menu **Options** (écran Pause, `scenes/OptionsScene.ts`) : réglettes de volume à 10 crans (`settings.ts`, lecture via `music` de l'engine ; la musique est ÷6 au cran maximal : `MUSIC_MAX_GAIN`), **Hotkeys** (page de l'écran Options, `scenes/hotkeysPage.ts`, pas sur téléphone) : le joueur réassigne les touches de **déplacement** (haut / bas / gauche / droite, défaut WASD), les **choix d'upgrade** 1 / 2 / 3 et la **relance** (R) — clic sur la touche puis appui sur la nouvelle (Échap annule ; Échap / Entrée / P refusées ; une touche déjà prise est échangée ; « Rétablir par défaut ») ; touches par code **physique** (`hotkeys.ts`, `settings.hotkeys` / `moveKeys()`, `MoveInput` de l'engine avec l'option `keyCodes`), donc WASD = ZQSD sur un AZERTY sans rien régler ; **les flèches restent toujours actives** (le pavé numérique ne déplace plus la squad) ; le tutoriel affiche les touches choisies. **Rejouer le tutoriel** (confirmation, quitte la partie), langue (**anglais par défaut**) et, en dev, **mode debug** qui affiche les boutons des outils de dev. Les réglages (musique, bruitages, mutes, zoom, FPS, debug) sont mémorisés d'une session à l'autre (`localStorage`, préfixe `xiao-swarm:` posé en tête de `settings.ts`). Par défaut : musique et bruitages au cran 5/10 (`MUSIC_DEFAULT`, `SFX_DEFAULT`) ; en dev, mode debug activé.
Outils de dev (détail : `docs/OUTILS_DEV.md`). **En ligne** : `?debug=1` active les outils de dev dans un build déployé (`DEV_TOOLS` de l'engine, à utiliser à la place de `import.meta.env.DEV` pour tout outil de dev ; seul le Save vers le code reste lié à `import.meta.env.DEV`). Visionneuses (boutons **en bas à gauche** du jeu en mode debug, contour **vert** pour ceux qui ouvrent une vue plein écran, ou `?viewer` / `?particles` / `?obstacles` / `?misc` / `?bonus` / `?upgrades` / `?waves` / `?mapedit`) : **unités**
(animations, ancrage par séquence / direction, bouche du canon par frame), **particules** (`fxParams.ts`), **obstacles**
(hitbox en cercles, jeu de taches, taille : `data/obstacles.ts`) **vagues** (Gestionnaire de vagues : 9 niveaux de configurations tirées au hasard + timeline : `data/waves.ts`) **divers** (projectiles, bonus, interface, terrain) et **carte** (zones d'obstacles de l'arène solo / coop : `data/mapZones.ts`, un obstacle tiré au hasard par zone à chaque partie avec la seed, donc identique chez tous les joueurs).
Une croix en haut à droite du panneau de chaque vue ramène au jeu ; pour changer de vue, repasser par le jeu (boutons du HUD).
**Convention de toute vue avec des valeurs réglables : boutons Save et Reset.** Save écrit les valeurs comme valeurs par défaut dans le code
(plugin Vite `games/xiao-swarm/dev-save.ts` : `config.ts`, `fxParams.ts`, `assets/manifest.ts`, `data/obstacles.ts`, `data/waves.ts`, `data/mapZones.ts`) ; Reset revient à la dernière
sauvegarde. Toute nouvelle vue de réglage doit suivre cette règle. Elles mémorisent aussi leurs réglages dans le navigateur (localStorage) : en dev ces copies masquent le code. Chaque copie est marquée avec une empreinte des
valeurs du code (`dev/staleOverrides.ts`, `dropStaleOverride` appelé en tête de chaque `load…Overrides`) : si le code par défaut a changé, la copie est supprimée
au démarrage et signalée dans le HUD (« Réglages mémorisés périmés supprimés »). **Toute nouvelle copie mémorisée doit appeler `dropStaleOverride`** avec les valeurs du code qu'elle remplace.
**Équilibrage sans réglage caché** : tout réglage global d'équilibrage (stats des aliens / boss / zombies / squad, multijoueur, plafonds et rejeu des vagues, aides au joueur) vit dans `DIFFICULTY_DEFAULTS` (`config.ts`) et a son curseur dans le panneau **Difficulté** (`DIFFICULTY_SECTIONS` de `debugDifficulty.ts`) ; le contenu et le rythme des vagues dans le Gestionnaire de vagues ; les stats propres à chaque unité dans le panneau Stats. Ne pas réintroduire de multiplicateur d'équilibrage en constante cachée (ex. l'ancien `WAVE_PRESSURE`, remplacé le 08/10 par l'effectif par entrée `TimelineEntry.mul`, visible dans le Gestionnaire de vagues).

Test en navigateur : `?net=host&bot=2` (coop avec 2 coéquipiers IA) ; en dev `window.__game`, le **menu Réglages** (touche `²`/F2 ou
bouton à curseurs en haut à gauche du HUD : zoom du jeu, réglages visuels, stats) et trois panneaux dédiés ouverts par des boutons du HUD (ces menus s'ouvrent toujours à gauche, côte à côte dans l'ordre d'ouverture) :
**Foule** (sliders du mouvement de foule `CROWD` dans `config.ts`, mémorisés dans le navigateur ; **F8 / F9** = sauvegarder /
charger une config de travail), **Difficulté** (multiplicateurs globaux `DIFFICULTY` de `config.ts` : PV / dégâts / vitesse / nombre d'aliens, PV des boss et des soldats ; Save / Reset ; `alienDamageMul` s'applique dans `Sim.damageSoldier` aux coups sans `attacker`, sauf les « un coup = un mort » passés avec `scaled` = false) et **Triche** (ajouter / retirer des soldats par classe, faire apparaître ou tuer des aliens,
recrues, vagues, vitesse du jeu, invincibilité ; hors ligne seulement). `npm run sim:crowd` mesure la réactivité,
`npm run sim:recruit` où une recrue s'insère dans la formation.

## Jeu : structure actuelle
- Carte solo / coop : `makeJungleMap(seed)` (`data/maps.ts`) tire les obstacles dans les zones de `data/mapZones.ts` (éditeur : vue Carte). Mode de jeu : la **survie** (`survival` dans `data/modes.ts`, un seul mode depuis le 08/10 : l'ancien mode `coop` y est fusionné), jouable **seul** (hors ligne : pause, revive par pub, tutoriel, boss final ~10:00 = victoire) ou **à plusieurs** en ligne (humains et/ou coéquipiers IA, pas de tir ami, difficulté qui grandit avec les joueurs vivants, XP partagée, zones de réanimation, spectateur, relance). Ce qui change en ligne dépend de `SimConfig.online` (posé par `HostSession` / `ClientSession`), jamais du mode. Les modes **versus** (PvP) et **battle royale** viendront plus tard : **désactivés pour l'instant** (`GameScene.pickMode` joue toujours la survie, `?mode=royale` est ignoré) ; leur code reste (`MODES.royale` / `MODES.versus`, `sim:headless -- royale`).
- Vagues : `data/waves.ts` (niveaux 1-9 → configurations tirées au hasard, timeline, boss via `config` forcée ; **effectif par entrée** `mul` : groupes hors boss × `mul`, arrondi, au moins 1, colonne « Effectif × » et barres raccourcies dans le Gestionnaire ; la pression du build Poki 0.1.38 (ancien ×0,8 de 2:00 à 5:00 et après 6:00) est reproduite en **supprimant 30 envois** de la timeline (±1,5 % par minute) ; les vagues **rejouées** pendant un combat de boss prennent en plus × `DIFFICULTY.bossReplayMul` (0,8, panneau Difficulté, section Vagues)), exécutées par `sim/WaveRunner.ts`. Le gestionnaire est **figé** (`cursor` ne bouge plus) : (1) tant qu'un **boss est vivant** — il renvoie alors en boucle les `DIFFICULTY.bossReplayCount` (5) derniers envois d'avant le boss (écarts plafonnés), dont les aliens ont `AlienState.noXp` (aucun globe d'XP : pas de farm en laissant le boss en vie) ; (2) quand il y a plus de `DIFFICULTY.wavePauseAbove` (150) aliens vivants, jusqu'à `DIFFICULTY.waveResumeAt` (100) ; `WaveRunner.suspended`. Pendant un boss, sa barre de vie (HUD) remplace la timeline en haut de l'écran.
- Sauvegarde (`localStorage`, préfixe `xiao-swarm:`) : `SAVE_VERSION` dans `settings.ts` — l'incrémenter remet à zéro chez tous les joueurs le tutoriel (`settings.tutorialDone`), le compteur de parties (`gamesPlayed`, interstitielles) et le record (`bestTime`) ; les réglages (volumes, mutes, langue, zoom…) sont conservés. À faire quand une version doit rejouer l'onboarding.
- Onboarding : première partie solo `survival` (`settings.tutorialDone`, bouton « Replay tutorial » des Options) : `sim/Tutorial.ts` + `data/tutorial.ts` remplacent la timeline de vagues au début (point vert, 3 vagues, recrue du slime qui saute sur place, level-up imposé, HUD allégé, cadeau caché de fin `TUTORIAL_REWARD`) puis le gestionnaire de vagues normal démarre à 0 s ; la squad n'y meurt pas. Base de toute squad : `DIFFICULTY.squad*` (dégâts ×1,2, cadence ×1,15, vitesse ×1,08, recrues ×1,3 ; PV : `soldierHpMul` 0,91). Détail : `docs/TUTORIEL.md`.
- Courbe d'XP : `xpToNext` (`data/progression.ts`, table des niveaux 1-40) à **bosse de départ** : les premiers niveaux coûtent plus cher pour espacer les level-ups du début (niveau 2 : 42 XP, niveau 5 : 93), puis la courbe rejoint l'ancienne un peu en dessous ; l'XP cumulée du niveau 21 (≈ 6 min) reste 4684. Le niveau 1 reste à 10 (le tutoriel en dépend).
- Progression : à chaque niveau, l'onde de choc part tout de suite (texte « LEVEL UP! », animation commune `Fx.text`), puis `LEVEL_UP_DELAY` (1 s, `Sim.choiceDelay`) plus tard le jeu se met en PAUSE pour tous les joueurs (`Sim.choiceT`, passé dans le snapshot). Écran de choix (`scenes/LevelUpScene.ts`) : cartes **portrait** (`view/upgradeCards.ts` : fond par upgrade `ui_card_<id>`, prismatique `ui_card_prism`, icône, description, **slots** de progression sur 1-2 lignes de 5, « Claim » sur la plaque), titre et bouton Reroll en images ; un clic ne compte qu'appui + relâchement dans la fenêtre (`pressed`). Relances d'upgrade : `Squad.rerolls` (2 par partie). Aux niveaux **10, 20, 30…** (`PRISM_LEVEL_EVERY`), les 3 propositions sont **prismatiques** (une relance les retire au sort normalement) ; sinon chacune l'est avec `DIFFICULTY.prismChance` (5 %). En ligne, 5 s (`UPGRADE_CHOICE_TIME`, option `choiceTimeout` de la Sim) puis choix au hasard ; en solo, pas de limite. En coop, une seule barre d'XP pour tous (seuil × nombre de joueurs).
- Ennemis : `data/aliens.ts` (capacités en données : `lob`, `tongue`, `rush`, `leap`, `spray`, `cloud` (cracheur : nuage violet ralentissant posé sur la squad toutes les 6 s, passe par `Sim.puddles`), `cleave` (mêlée en zone du chargeur), `frost` (chaman : 3 petits nuages de glace autour de la squad toutes les 9 s, 10 s chacun ; y entrer = gelé dans un glaçon, nuage consommé ; flaque `frost` de `Sim.puddles`), `deathBlast`, `revive`, `capture`, `trail`, `wall`, `lurk`, `dash`, `swarm` (Gling Mère : toutes les 4 s, 22 glings ; le chaman `revive` : 3 résurrections puis 30 s de repos, `maxRevives` / `lockout`), `ice` (slime de glace `iceballer` : il lance un **orbe de glace** = alien-projectile `ice_orb` (`def.projectile`, `Horde.launch` / `updateOrb` : 500 PV exacts, barre de vie toujours affichée, la squad peut le détruire, traînée de flocons, ombre portée, ni XP ni recrue, jamais recyclé) qui **gèle** le soldat touché ; le gel est un **état du soldat**, pas une unité : `SoldierState.frozen` = PV de gel (`FREEZE` dans `config.ts` : 50 PV, coups alliés ignorés 0,5 s au début) ; gelé, il ne bouge ni ne tire et reste attaquable par les aliens ; **chaque coup d'un allié** (balle, rayon, explosion ; en coop tous les joueurs) retire 1 PV de gel sans le blesser (`Sim.chipIce`, les soldats visent d'eux-mêmes un allié gelé à portée) ; glaçon dessiné sur sa vue (`SoldierView`, fissures par étages, il ne rétrécit plus ; à chaque coup allié, éclats et petits **blocs de glace** qui sautent en cloche : `Fx.iceShards`, texture `fx_ice_chunk`, réglages `FX.ice.chunk*` dans la visionneuse Particules), **barre bleue des PV du glaçon** au-dessus de sa barre de vie, elle-même toujours affichée tant qu'il est gelé (`WorldView`, `ICE_BAR_COLOR`), PV de gel dans le snapshot), `maxPerWave`, `boss` ; boss enragés : `DIFFICULTY.bossEnrage*`). XP / upgrades : `data/progression.ts`, `sim/Xp.ts`.
- **Rhinos jumeaux** (mini-boss de **7:30**, `boss_rhino_fire` + `boss_rhino_ice`, niveau 9 config 5, `data/waves.ts` ; sprites = planche de l'Alpha recolorée par `tools/hue-shift.mjs` avec intervalle de teintes) : deux Rhinos Alpha qui arrivent ensemble (1100 PV chacun). Leur charge (`rush`, calquée sur l'Alpha) a deux options en données : `rush.trail` (le rhino de **feu** sème des flammes pendant la charge, comme le slime de feu : `Sim.addFire` ; celui de **glace** sème des nuages de gel : `Sim.addPuddle(..., frost)`) et `rush.burst` (à la fin de la charge, **8 orbes** dans 8 directions régulières, le 1er dans le sens de la charge : `Horde.rushBurst` → `Horde.launch`). Orbe de glace inchangé ; **orbe de feu** (`fire_orb`, alien-projectile destructible de 500 PV, `projectile.kind: 'fire'`) : il laisse une traînée de flammes au sol (`def.trail`) et brûle le soldat touché (dégâts + flamme, pas de gel). **Il faut tuer les deux** : le clear screen du premier épargne l'autre, et seul le dernier tué termine le boss (bandeau « boss tué », escalade ×1,1 une seule fois) et laisse **le coffre**, sur lui. La barre de vie du HUD suit le premier boss vivant. Test : `?jump=twins`, `sim:combat`.
- Difficulté globale : `DIFFICULTY` dans `config.ts` ; power-ups : `sim/PowerUps.ts` ; zones de réanimation (coop) : `Sim.reviveZones`. Les cailloux (éléments des murs du `thrower`, télégraphe jaune dans `Sim.walls`), flaques, flammes des burners (`Sim.fires`, `WorldView.syncFires`), power-ups et zones passent par le **snapshot** (pas seulement des événements, qui sont non fiables).
- Boucliers : `shield` / `maxShield` sur tout `Body` (consommé avant les PV dans `Sim.absorb`). **Aucun soldat n'a de bouclier** (le power-up `shield` et le bouclier des renforts express ont été retirés ; ne pas en réintroduire sans le demander) ; capacité `shield` d'un alien en données (`data/aliens.ts`, Scarab : 10 % de ses PV, régénéré après 5 s sans dégât). Barre bleue au-dessus de la barre de PV (`WorldView`, barre de boss du HUD).
- Paliers de dégâts : `data/damageTiers.ts` (seuils du multiplicateur de dégâts → texture du tir du Gunner : bleu > vert > orangé > violet > rouge) ; les textures passent dans le snapshot comme les autres projectiles.
- Tir des soldats (`Combat.update`) : **priorité à la libération d'un allié** à portée — glaçon d'un allié gelé ou bulle qui a avalé un allié (le plus proche des deux) — avant tout autre alien.
- **Globes au sol** (recrue, power-up, globe d'upgrade) : **même modèle, seule la couleur change** : même taille (`FX.recruit.displayScale`, 0,34 = taille d'origine de la recrue), même rond posé dessous (`drawPickupSpot`) et mêmes étoiles qui scintillent (`view/GlobeGlitter.ts`, réglages `FX.recruit.star*`) : l'**effet d'origine de la recrue** (étoile dorée `RECRUIT_STAR`), la même étoile décalée en vert / rose (`ensureStarTexture`) pour les autres ; recrue jaune, power-up vert (globe du bonus recrue décalé en vert, icône du bonus au centre : `view/PickupViews.ts`), globe d'upgrade rose.
- Ramassage : `sim/Pickup.ts` ; un objet au sol (globe d'XP, recrue, power-up) qui commence à être **attiré** (rayon d'un soldat ou aimant) est « attrapé » (`catchItem`, drapeau `caught`) : il ne disparaît plus et ne clignote plus jusqu'à être ramassé (`PICKUP.caughtLife`), **suit la squad qui l'a attrapé sans limite de distance** et **accélère** jusqu'à `PICKUP.maxSpeed` (`Pickup.chase` : `pullStart`, `pullAccel`) — une squad rapide ne peut pas le distancer ; la stat `magnet` (upgrade) multiplie rayon d'attraction, rayon de ramassage et vitesse max des recrues et des power-ups (`config.PICKUP`) ; le rayon d'attraction de base (`PICKUP.magnetRadius`) est commun à tous les objets au sol, globes d'XP compris (`Xp.ts`, qui accélèrent aussi avec `magnet`). Une recrue qui apparaît saute en cloche vers la squad du tueur (`config.RECRUIT`).
- Revive : hors ligne, **rewarded** (une fois par partie) ; la squad revient à `DIFFICULTY.reviveSquadFraction` (60 %) de son **effectif maximal** de la partie (`Squad.peakComposition`, classes réparties) ; la partie qui commence par le tutoriel offre un **Free Revive** (un seul bouton, `GameOverScene`, sans pub) dont l'onde de choc **détruit** les aliens (`Sim.respawnSquad(…, lethal)`, boss seulement repoussés).
- HUD en images : timeline / capsule « NEXT BOSS: » / jauge circulaire (`view/TimelineHud.ts`), barre d'XP et barre de vie du boss (cadre vide + jauge 3-slice, part blanche du boss comme les barres de vie des aliens), boutons (`HudButtons.ts`). Mesures dans `TIMELINE_ART`, `XP_ART`, `BOSS_ART`, `CARD` ; images produites par `tools/*.mjs` (voir `docs/OUTILS_DEV.md` § Outils d'art).
- Textes flottants de la squad (`Fx.text`, `iconText`) : une seule animation (`FX.text`), la **montée est additive** (jamais un tween sur `y` : il écraserait le suivi `follow` de la squad) ; ils suivent `WorldView.squadFocus` (positions interpolées).
- **Unités enterrées** — règle visuelle commune à **toute** unité qui s'enfouit ou se désenfouit (apparition de vague dans son trou, Scarab, lurker, recyclage des traînards, futurs ennemis) : son sprite est **rogné par le bas** et descend dans le sol / en remonte (`AlienView.groundCut`, ligne de sol au point d'ancrage), et son **ombre portée** disparaît / réapparaît en fondu (`outOfGround`) ; trou de la taille de l'ombre (`drawHole`). Le lurker est le seul à s'arrêter **à moitié** (semi-enterré, reste un peu visible pour attaquer, d'où ses 50 %). Règles (`BURIED` dans `config.ts`, `Horde.burial` / `Horde.targetable`) : pendant les animations (s'enterrer, se déterrer, recyclage) **100 %** des dégâts ; **semi-enterrées** (lurker en embuscade, généralement immobiles) **50 %** des dégâts, seuls les **30 % du haut** du sprite dépassent du sol (`BURIED.semiShow`) ; **totalement enterrées** (Scarab qui se déplace sous terre) **intouchables**, invisibles, jamais visées ni touchées par les balles.
- **Coffre des boss** (`sim/Chests.ts`, `Sim.chests` / `Sim.upgradeOrbs`, réglages `DIFFICULTY.chest*` dans le panneau Difficulté) : chaque boss / mini-boss tué (sauf le final) laisse un **coffre** sur son cadavre, à la place de l'ancien aimant garanti. Un soldat de n'importe quelle squad resté à moins de `chestRadius` (100 px) pendant `chestTime` (2 s, la progression redescend quand personne n'est là) l'ouvre : il se détruit et libère `chestOrbs` (2) **globes d'upgrade par joueur vivant**, qui retombent en cloche autour de lui. Chaque globe est **réservé à son joueur** (`owner` : aucune autre squad ne peut l'attirer ni le ramasser, jamais d'expiration, l'aimant n'aspire que les siens), son upgrade est **tirée à la chute** et son icône est celle de la carte d'upgrade (`art/upgradeOrbs.ts`, assemblage façon bonus recrue décalé en rose + rond rose au sol, `view/LootViews.ts` ; **un joueur ne voit que ses propres globes**, ceux des autres joueurs ne sont pas dessinés) ; il est **imprenable la première seconde** (`chestOrbGrace` : on le voit d'abord retomber) ; le ramasser applique cette upgrade comme un choix de niveau (`Squad.grantUpgrade`, **jamais prismatique**, événement `upgradePicked` : même texte flottant ; déjà au maximum : une autre est tirée). Coffres et globes passent par le snapshot (protocole v44, `Mirror`). Testé par `sim:combat` et `sim:net`.
- **Escalade** : chaque boss / mini-boss tué rend tous les aliens qui apparaissent ensuite plus forts de +10 % (PV, vitesse, dégâts, cadence), cumulés ×1,1 par boss (`DIFFICULTY.bossEscalation` dans `config.ts`, réglable dans le panneau Difficulté, `Sim.bossKills` / `Sim.escalation`, `AlienState.esc`) ; remise à zéro à la relance. `npm run sim:combat` (dans `games/xiao-swarm`) vérifie le gel (dégel par les alliés, soldat gelé attaquable), escalade et repos du chaman.
- **Recyclage des traînards** (anti-fuite en rond, `Horde.relocateStragglers`, réglages `RELOCATE` dans `config.ts`) : un alien resté plus de 5 s à plus de 1000 px de toutes les squads (hors écran) tire au sort. **75 %** : il s'arrête et **s'enterre** (`AlienState.sinkT`, 0,6 s, trou + il s'enfonce ; drapeau `sinking` du snapshot, protocole v39) puis est remplacé par un alien neuf (nouvel id, mêmes PV / bouclier / escalade / marques `noXp` `noRecruit`) qui **ressort du sol** hors écran **devant** la squad la plus proche, dans sa direction de course (`Squad.vel`) — méthode Vampire Survivors. **25 %** (`flankChance`) : il passe en **mode contournement** (`AlienState.flank` ≠ 0, réglages `CHASE`, `Horde.chaseDir`) : il vise le premier point de la course **prévue** de la squad (`Squad.vel` / `Squad.turn`, ligne droite ou arc) qu'il peut atteindre à temps, décalé sur son flanc, pour l'encercler ; répit de `flankFor` (10 s) avant un nouveau tirage. Jamais un boss ni un alien occupé (bulle avec prisonnier, chaman qui incante, lurker enterré). `npm run sim:chase` (dans `games/xiao-swarm`) compare avec / sans sur une squad qui tourne en rond.
- Boss : enragement **sans fin**, un niveau toutes les 45 s après l'apparition (`DIFFICULTY.bossEnrageEvery`, +30 % vitesse / cadence et −30 % cooldown par niveau), mêlée en un coup (`oneShot`) pour les quatre. **Boss tué = clear screen** : tous les autres aliens meurent avec lui (`Sim.wipeAliens`) **comme si le joueur qui a tué le boss les avait tués** (XP et recrues selon leurs marques habituelles, flaques, explosion des kamikazes : pas de décalage d'XP entre ceux qui tuent le boss vite et les autres) ; un autre boss encore en vie est épargné. La timeline (`data/waves.ts`) envoie des vagues serrées juste après chaque boss pour que la carte vide ne reste pas calme. Vérifié par `sim:combat`. **Plafond d'aliens à l'apparition** (`Horde.canSpawn`) : `ModeDef.maxAliens` × `DIFFICULTY.alienCountMul` = **150 par joueur vivant** en survie et coop (135 avant le 08/10), +12 places pour les aliens de 60 PV et plus ; un **boss l'ignore** (carte pleine, il était sauté sans bruit). En plus, la timeline se met en pause au-delà de `DIFFICULTY.wavePauseAbove` (150 vivants au total, reprise à 100). XP : un alien **invoqué** (essaim de la Gling Mère), **ressuscité** (chaman) ou envoyé par un **rejeu de vague** pendant un boss ne laisse jamais de globe (`AlienState.noXp`, `Horde.spawnAt`) ; un alien invoqué ou ressuscité ne laisse non plus aucune **recrue** (`AlienState.noRecruit`), mais ceux d'un rejeu de vague peuvent en laisser. Scarab : vitesse ×3, s'enterre toutes les 5 s ; sous terre, son télégraphe vise **le centre de la squad** (sans anticipation) puis, `burrow.lock` (1,5 s) avant qu'il ressorte, sa **direction se fige** (celle de la course de la squad à cet instant, `rushDx` / `rushDy`) : il continue d'avancer sur cet axe au rythme de la squad (part de `Squad.vel` le long de l'axe), donc filer tout droit ne sauve pas, il faut s'écarter sur le côté ; en ressortant il vise où sera la squad dans `burrow.lead` (1 s) et fonce tout droit vers ce point, **direction verrouillée**, jusqu'à l'atteindre (phases 3-4 de `lurkPhase`) ; une fois sorti, **pluie de stalactites** (`def.stalactites` : 6 petites zones, 3 sur des soldats, télégraphe 1,1 s, 80 dégâts ; `Sim.stalactites`, passent par le snapshot, protocole v40) ; quand il **marche** vers la squad entre deux plongées, une petite pluie de 3 (2 sur des soldats) à mi-chemin du compte à rebours (`stalactites.walk`). Plus de slam (l'étourdissement `SoldierState.stun` reste disponible pour un `slam` à `stun`).
- Réseau (protocole actuel **v45**) : toute nouvelle donnée visible chez un client doit passer par `net/Protocol.ts` (snapshot) ou un `SimEvent`, et `Mirror` ; incrémenter `PROTOCOL_VERSION` si le format change. Un champ conditionnel de l'encodeur binaire doit tester l'octet **écrit** (borné), pas la valeur brute : sinon le décodeur se décale et tout le snapshot est faux (voir `docs/MULTIJOUEUR.md` § Pièges). La squad locale d'un client est prédite (`net/Prediction.ts`). Monde figé chez l'hôte (pause de choix, écran de fin) : `Mirror` n'extrapole plus rien (sinon les projectiles tremblent). Depuis le protocole v38 : positions au 1/4 de pixel sur 16 bits (`Writer.pos`, cartes < 8192 px), effets de tir `shot` / `impact` / `hit` en binaire dans le snapshot (pas en JSON), et **tampon d'interpolation** de 100 ms chez le client (`INTERP_DELAY_MS` dans `ClientSession.ts`, 0 = désactivé) ; détail et retour en arrière : `docs/MULTIJOUEUR.md` § Optimisations v37-v38. Protocole v43 : aliens compressés (id 24 bits, **pas de vitesse** : le client l'interpole vers le snapshot suivant de son tampon, `Mirror.apply(snap, next)` ; PV max u16, drapeau 32 = f32 pour les boss).

## Règles d'architecture (multijoueur battle royale ~10 joueurs prévu)
1. `games/*/src/sim/`, `data/`, `net/`, `config.ts` sont **purs** : pas de Phaser ni DOM, imports depuis
   `@xiao/engine/sim` uniquement (vérifié par `tsconfig.sim.json`).
2. Tout l'aléatoire de la simulation passe par `sim.rng` (seedé). Jamais `Math.random` dans `sim/`.
3. La simulation émet des `SimEvent` et ne touche jamais l'affichage ; `view/` lit l'état, interpole, joue les effets.
4. Toute action d'un joueur passe par `PlayerInput` ; une `Session` fait avancer la simulation (pas fixe 30 Hz).
5. Contenu = données (`data/`), logique = systèmes génériques. Code générique → engine.
6. `data/obstacles.ts` (visuel + hitbox + taches) est pur et partagé sim / affichage ; `fxParams.ts`, `settings.ts`, `debug*.ts`, `dev/` et les visionneuses sont côté affichage / dev.
7. Un champ ajouté à un objet recyclé par `Pool` (ex. `Projectile`) doit être remis à zéro à la libération.

## Poki
**Pubs activées** (`ADS_ENABLED = true` dans `packages/engine/src/poki/poki.ts` ; `false` les coupe toutes) : **rewarded** pour le revive (hors ligne, un seul par partie ; le revive du tutoriel est gratuit, « Free Revive », et sans pub) et **interstitielle entre deux parties** (« Rejouer », relance coop) mais **désactivée pour l'instant** (`INTERSTITIALS_ENABLED = false` dans `config.ts` ; une fois activée : pas avant les 3 premières parties, `FREE_GAMES`, compteur `gamesPlayed` mémorisé). **Pas de pub à la sortie d'une pause.** Les règles ci-dessous valent.
Événements SDK obligatoires (https://developers.poki.com/guide/requirements-quality), tous passent par `RunFlow` / `poki` (le moteur filtre les doublons et les appels pendant une pub) :
- `gameLoadingFinished()` : une fois, quand les assets essentiels sont chargés (`BootScene`).
- `gameplayStart()` : au **premier input du joueur** (jamais au chargement), puis à chaque retour en jeu (sortie de pause, fin du choix d'upgrade, relance).
- `gameplayStop()` : à **toute interruption** : pause, menu Options, mort, fin de partie (y compris l'écran de fin coop `gameEnd`), connexion perdue. Jamais deux de suite, jamais pendant une pub. **Le choix d'upgrade n'est PAS une interruption** : c'est du gameplay, pas de `gameplayStop`.
- `commercialBreak()` : uniquement **entre deux parties** (retry, relance coop) à partir de la 4e partie (`RunFlow.restart({ ad })`) ; jamais pendant une pub, jamais à la sortie d'une pause. Pas de timer de pub maison.
- `rewardedBreak()` : uniquement sur choix explicite du joueur (revive solo).
- Non obligatoires mais utiles : `poki.measure(...)` / `poki.measureOnce(...)` (analytics du comportement : tutoriel, paliers de temps et de niveau, boss, mort, upgrades, revive, rétention). Catalogue et règles : `docs/ANALYTICS.md` ; tout nouvel événement part de la vue (jamais de `sim/`) et s'ajoute à ce catalogue.
En ligne la partie ne se met jamais en pause (l'hôte gèlerait tout le monde) : seuls l'écran de fin et la perte de connexion émettent `gameplayStop`. Le menu Options en ligne n'arrête pas le jeu, donc pas de `gameplayStop`.
Pas de requête externe hors SDK, pas d'écran titre, `gameplayStart` au premier input, pas de timer de pub maison,
bouton rewarded jamais vert et jamais plus gros que l'option standard, jouable en incognito et avec adblock.
