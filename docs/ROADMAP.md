## À faire

0. **Boilerplate (priorité)** : extraire dans `@xiao/engine` les briques génériques nées dans Xiao Swarm — plugin dev-save + outils de dev (`devUi`, panneaux), moteur de vagues (`WaveRunner` + éditeur), XP / upgrades / `LevelUpScene`, grille d'obstacles + glisse (`Arena`) — puis compléter `games/_starter` (exemple de chaque brique), écrire `docs/NOUVEAU_JEU.md`, vérifier en CI que le starter compile avec l'engine seul, script `npm run new-game`.
1. **Équilibrage** : la difficulté (PV des ennemis, effectifs par niveau ×1,15 → ×2,3, boss) a été réglée avec un bot ; à affiner en jeu, puis panneau **Équilibrage** dev (`CROWD.stillDelay`, dégâts, PV, cadences). Le Rhinocéros Alpha (45 PV par soldat touché) est à surveiller.
2. **Test à deux joueurs** en vrai (latence réelle, 3-4 joueurs) : seuls les tests automatiques en mémoire (`sim:net`, `sim:predict`) ont été exécutés ; **valider la prédiction** avec le throttling du navigateur (100-200 ms + perte) : régler `BLEND` / `SNAP` (`net/Prediction.ts`) si la squad « tire » en arrière, ajouter de l'inertie aux soldats prédits si l'arrêt est trop sec.
3. **Contenu** : réactiver Medic, Flammeur, Sniper, Tank, Grenadier  ; sprites dédiés pour les nouveaux ennemis (aujourd'hui recolorés du slime, ou procéduraux : lurker, thrower…) et visuel des murs du thrower (aujourd'hui des rochers gris) ; **relance coop** : la carte n'est pas retirée (même carte dans une session) — la reconstruire chez l'hôte et les clients si on veut une carte neuve à chaque relance.
4. **Perf rendu** : Phaser n'écarte pas les sprites hors caméra ; ajouter un culling dans `WorldView` (aliens, décor, flaques) puis mesurer les fps avec 300-600 aliens.
5. **Pubs Poki** : remettre `ADS_ENABLED = true` (`packages/engine/src/poki/poki.ts`) avant la soumission, puis retester avec de vraies pubs la séquence `gameplayStart / Stop` (pause, relance, relance coop, revive) ; les événements obligatoires sont listés dans `CLAUDE.md`.
6. **M6 — Onboarding & polish Poki** : tuto, écran de fin hors ligne, audio, traductions EN/FR/IT/DE/ES/TR, Poki Inspector, miniatures.
7. **Battle royale** : zone qui rétrécit, UI de fin, puis serveur Node autoritaire pour ~10 joueurs (snapshots delta, interest management).
8. **Obstacles** : affiner hitbox et taches dans la visionneuse (puis Save).
9. **Session du 01/10, suites** : planches **idle** dédiées des aliens (aujourd'hui = cycle de marche ralenti ; l'utilisateur va les générer) ; tester en ligne l'écran « En attente des autres joueurs » ; réglages des roquettes dans la visionneuse Particules ; option « Fond étoilé » dans le menu Options (perf mobile) ; mesurer le gain de FPS sur téléphone avec `?space=0` ; garder ou non les blobs du crabe en plus du saut ; champs de nom des unités (FR / EN) retirés de la visionneuse pour l'instant (module `debugNames.ts` gardé).

10. **Netcode, suites** (détail et ordre de rentabilité dans [MULTIJOUEUR.md](MULTIJOUEUR.md) § Pistes d'amélioration) : interpolation des entités distantes (tampon ≈ 100 ms), événements importants en canal fiable, perte et gigue dans `LoopbackHub`, bande passante (delta, interest management) si > 4 joueurs, serveur Node autoritaire.
11. **Upgrades** : l'impression de « renoncer » vient du tirage (1 carte sur 3, aucune relance, 10 upgrades à plafonds pour peu de niveaux). Piste recommandée : 2 **relances** par partie (à synchroniser en ligne : snapshot + message), sinon bannissement, garantie anti-malchance ou courbe d'XP plus rapide (`data/progression.ts`, `Squad.rollOffer`).
12. **Visuel du globe d'XP** : source `art-src/globe_xp.png` ; le jeu charge `public/assets/fx/xp.webp` (à régénérer après chaque changement de la source : conversion WebP sans redimensionnement) ; `pannel.png` (nouveau, non utilisé) en attente.

## Points d'attention

- **Protocole réseau v20** (v20 : ancre, vitesse et `ack` d'input par squad pour la prédiction ; inputs numérotés) : le snapshot porte les murs annoncés du thrower (`walls`), la phase du lurker et l'origine du couloir de charge du rhinocéros (`rushX` / `rushY`), en plus de XP / niveau / propositions / upgrades par squad, temps de choix d'upgrade (`choiceT`), globes d'XP, état des charges, saut du crabe, chaman et bulle ; hôte et client de versions différentes se refusent. Les cartes viennent de la seed et des données : mêmes fichiers `data/` chez tous.
- **Snapshot binaire** : un champ conditionnel de l'encodeur doit tester l'octet écrit (arrondi, borné), pas la valeur brute, sinon le décodeur se décale et tout le snapshot est faux (cas réel : `rushWind` négatif du rhinocéros). À tester **après** la fin de la capacité, pas seulement pendant. Voir [MULTIJOUEUR.md](MULTIJOUEUR.md).
- **Projectiles recyclés** (`Pool`) : un champ ajouté à `Projectile` doit être remis à zéro à la libération (`Combat`).
- **Script de vagues en dev** : le navigateur mémorise le script édité (localStorage) ; après une modification de `data/waves.ts`, faire **Reset** dans le Gestionnaire de vagues.
- **Navigateur du panneau de test** : boucle de jeu très lente ; `window.__game.step(t, dt)` pour avancer à la main, voir [OUTILS_DEV.md](OUTILS_DEV.md).
- **Phaser 4 / WebGL** : au-delà de ~5 grandes textures distinctes dans un même lot, certaines s'affichent en noir → sol en morceaux de 2048 px + masquage hors caméra (`view/ArenaView.ts`).
- **Windows PowerShell** : `npm` peut être bloqué par la politique d'exécution → utiliser `npm.cmd`.
- **Poki** : toute requête externe (serveur multi, analytics) doit être approuvée (Settings → CSP).
